# My USJ — Schedule Planner

## Установка поверх текущей версии member-портала
1. Сделайте резервную копию проекта. Распакуйте архив в корень с сохранением папок.
2. Обновляются только `src/main.tsx` (маршрут) и `src/components/Shell.tsx` (навигация). Если эти файлы менялись после присланного архива, перенесите их изменения вручную; остальные файлы планировщика новые.
3. `npm ci`, затем `npm run build`. Дополнительные npm-пакеты не нужны.
4. Для сохранения в аккаунте выполните в Supabase SQL Editor содержимое `supabase/migrations/20261027000100_member_schedule_planners.sql`. Сначала проверьте миграцию на staging/резервной копии.
5. Разверните через обычный Vercel/Git-процесс. Новый маршрут — `/my-usj`.
6. Проверьте доступность нового пункта My USJ в боковом меню и More на телефоне.

Ни публикация, ни SQL-миграция автоматически не выполнялись. Рабочая база не изменялась.
Если SQL пока не выполнен или сервер недоступен, планировщик работает с локальной копией и экспортом JSON; кнопки аккаунтного сохранения недоступны, причина показана в интерфейсе.

## Что сделано
- Категория My USJ перед You; Planner и существующий Résumé Builder в одном разделе.
- Вкладки Schedule planner, Career toolkit и Campus resources.
- Недельная сетка, дневной мобильный вид, автоматическое появление выходных, динамический диапазон часов.
- Цвета курсов, несколько встреч у курса (например, лекция и лабораторная), аудитории, преподаватели, кредиты, заметки.
- Курсы без фиксированного времени учитываются в кредитах, но не выдумывают блоки на сетке.
- Наложения проверяются для включённых курсов; соседние интервалы не считаются конфликтом. Пересечения показываются параллельными блоками с предупреждением.
- Поиск в личном списке по коду, названию, CRN и преподавателю.
- Включение/исключение курса без удаления: удобно пробовать альтернативы.
- До 12 планов, дублирование, сравнение в горизонтальной ленте, переименование и разные семестры.
- Копирование CRN по одному и всех включённых уникальных CRN вместе.
- JSON-экспорт/импорт с валидацией и подтверждением замены.
- ICS-экспорт повторяющихся встреч на выбранный период в America/New_York и печать текущего вида.
- Ресурсы: официальные MyUSJ, Academic Advising и сайт USJ. Существующий конструктор резюме не переписывался.

## Принципиальные ограничения
- Это личный планировщик LPS, НЕ официальная регистрационная система USJ.
- Каталог курсов не подключён: пользователь вводит курс из официального MyUSJ вручную.
- Места, prerequisites, advisor clearance, degree audit и фактическая регистрация не проверяются. Отсутствие конфликта по времени не означает разрешение записаться.
- ICS повторяет занятия еженедельно. Каникулы, праздники, отмены, исключения и финальные экзамены автоматически не загружаются: пользователь должен уточнить и исправить их в календаре.
- Короткие встречи показывают меньше текста; полное описание доступно по наведению/открытию курса и в списке.
- У чисел на мини-карточках планов нет статуса официальных кредитов/регистрации.
- Планы не делятся с другими участниками. Экспортированные JSON-файлы могут содержать личное расписание — храните их соответственно.
- Локальное хранилище разделено по ID аккаунта, но не зашифровано. На общем компьютере не оставляйте личные планы без необходимости. Sign out не удаляет браузерную копию; удалить её можно через настройки данных сайта (это также удалит другие данные сайта).

## Сохранение
Изменения автоматически сохраняются в браузере под ключом, содержащим ID текущего пользователя.
`Save to account` отправляет снимок всех планов в одну личную запись Supabase.
На новом устройстве без локальной копии аккаунтная копия загружается автоматически, если пользователь ещё не начал редактировать.
Если локальные планы уже есть, они не заменяются молча: для замены есть `Load account copy` с подтверждением.
Конкурирующее сохранение с другого устройства проверяется по `updated_at`. При несовпадении серверная копия не перезаписывается; экспортируйте локальные изменения и загрузите аккаунтную копию.
Миграция включает RLS: пользователь читает/меняет только строку со своим `auth.uid()`. Привилегированные администраторы БД по-прежнему могут иметь доступ.

## Проверки перед публикацией
Локально выполнены production build / TypeScript, 11 тестов модели, 14 UI-проверок и отдельные проверки сохранения с имитированным сервером.
Проверялись ширины 320, 390, 768 и 1440 px; добавление курса, дубли CRN, конфликт, исключение курса, копия плана, выходные, импорт и экспорт, ссылки ресурсов и диалог с Escape.
Сетевая часть аккаунтного сохранения проверялась на mock-ответах, не на рабочем Supabase. SQL и RLS необходимо отдельно проверить на staging: пользователь A не должен читать/менять строку B; анонимный пользователь не должен иметь доступ.
Рекомендуется дополнительно проверить: сохранение/загрузка на двух реальных устройствах после миграции, ошибки сети, импорт ICS в используемый календарь, основной логин и мобильное меню.
Показанные на превью классы, CRN и преподаватели — вымышленные тестовые данные; в production новые пользователи начинают с пустого плана.
