E-BOARD PORTAL — КАРТИНКИ И ЛОГОТИПЫ В ПИСЬМАХ

Патч к вашему последнему eboard-portal-main.zip.
В архиве только 17 изменённых/новых файлов проекта + эта инструкция,
отчёт QA и список SHA256. Нет node_modules, dist, .env или секретов.
На рабочий сайт/базу ничего не установлено. Реальные письма не отправлялись.

ВАЖНО: нужны ВСЕ ТРИ ЧАСТИ: SQL + две Edge Functions + обновление сайта.
Только замена файлов сайта или только SQL не включит картинки в письмах.

1. РЕЗЕРВНАЯ КОПИЯ
Сохраните текущие исходники, схему/данные Supabase и исходный код двух
почтовых Edge Functions. Лучше сначала проверить на тестовом проекте.

2. SUPABASE → SQL EDITOR → NEW QUERY
Откройте файл:
  supabase/migrations/20261030000200_announcement_email_images.sql
Скопируйте ВЕСЬ код и нажмите Run в том же Supabase-проекте, которым
пользуется E-Board Portal. Миграция добавляет announcements.email_images,
ограничения метаданных, bucket announcement-images и политики доступа.
Остальные миграции проекта повторно запускать не надо.
Миграцию можно повторить: она рассчитана на повторное применение.

3. SUPABASE → EDGE FUNCTIONS
Обновите код ДВУХ УЖЕ СУЩЕСТВУЮЩИХ функций и нажмите Deploy.
Фронтенд присланного проекта вызывает именно такие URL-slugs:

  rapid-worker  ← весь supabase/functions/welcome-email/index.ts
    Отправка всем активным участникам, welcome-письма и существующие notices.

  smart-api     ← весь supabase/functions/announce-email/index.ts
    Отправка объявления адресатам E-Board.

Ориентируйтесь на slug в URL функции: /functions/v1/rapid-worker и
/functions/v1/smart-api. Папки исходников называются welcome-email и
announce-email; это НЕ означает, что нужно создать новые функции под
этими именами. Сопоставление уже задано в src/lib/admin.ts вашего проекта.

Каждый index.ts самодостаточен: дополнительных shared-файлов для деплоя
Edge Functions не требуется. Сохраните прежние секреты и настройки
авторизации. Новых Resend API keys/SMTP-паролей не нужно. Секретные ключи
не должны попадать в VITE_* переменные, браузер, Git или чат.
Если реальные slugs у вас отличаются, сначала согласуйте src/lib/admin.ts
с реально вызываемыми функциями, а не разворачивайте неиспользуемую копию.

5. КАК ПОЛЬЗОВАТЬСЯ
Announcements → New Announcement или Edit:
- В поле Message поставьте курсор между нужными абзацами.
- Нажмите + Add image / logo и выберите файл с компьютера/телефона.
- PNG/JPEG/WebP до 10 MB автоматически уменьшается и перекодируется
  в PNG/JPEG, не больше 1 MiB на сохранённый файл. SVG/GIF/HTML запрещены.
  Прозрачность PNG/WebP сохраняется; анимация не поддерживается.
- Можно вставить до 6 файлов. Имя исходного файла не используется в URL.
- Под картинкой задайте Description (альтернативный текст; не подпись
  под изображением) и размер: Logo 160 px / Medium 320 px / Full width 512 px.
- В тексте появится [[image:...]]. Не изменяйте содержимое этой метки.
  Чтобы переместить картинку, перенесите всю метку между другими абзацами.
- Remove image убирает картинку и метку из объявления/будущего письма.
- Сохранение и переход к рассылке блокируются до конца загрузки.
- Изображения сохраняются при повторном открытии объявления.
- Email All Members → Review показывает персональное письмо с картинками;
  затем остаются прежние Continue и отдельное обязательное подтверждение.
  Одна загрузка/предпросмотр НЕ отправляет письмо.

Фирменная шапка LPS и подпись отправителя остаются прежними. Загруженные
логотипы вставляются дополнительно В ТЕЛО письма, не вместо фирменной шапки.
Поддержаны и рассылка всем участникам, и Email the Board.

6. ХРАНЕНИЕ И БЕЗОПАСНОСТЬ
- Bucket announcement-images публичный для предпросмотра. Загружайте только
  материалы, которые можно публиковать: афиши, логотипы, фотографии с разрешением.
  Никаких приватных документов, контактов или персональных записей.
- Загружать могут только активные President / Vice President / Faculty Advisor,
  как и публиковать объявления. Рассылка всем участникам остаётся только у
  President / Vice President. Major Leads новые права не получают.
- Путь загрузки ограничен собственной auth-user папкой. Нельзя перезаписывать
  или удалять эти файлы из клиентского приложения. Неиспользуемые загрузки
  могут оставаться в bucket; очистка — административная, с проверкой ссылок.
- Сервер читает только проверенные пути собственного bucket; внешние URL
  не скачиваются. Проверяются лимит, формат метаданных, сигнатура PNG/JPEG.
- В письме картинки отправляются как inline CID-вложения через Resend,
  а не как временные ссылки. Изображение скачивается сервером один раз до
  начала рассылки. При отсутствующем/невалидном файле ничего не отправляется.
- Уже доставленное письмо не меняется от редактирования объявления.
  Почтовый клиент получателя всё равно может скрыть изображения по своим правилам.

7. ПРОВЕРКА ПОСЛЕ УСТАНОВКИ
На тестовом окружении с одним тестовым участником:
- вставьте PNG-логотип между двумя абзацами, выберите Logo 160 px;
- сохраните без email, откройте Edit и проверьте описание/размер;
- проверьте Review на компьютере и телефоне, затем подтвердите тестовую отправку;
- проверьте реальное письмо в Outlook/Gmail: изображение, подпись, порядок текста;
- проверьте Email the Board на тестовом получателе;
- проверьте, что Major Lead не может загружать или отправлять такие письма.
НЕ используйте реальную рассылку всем участникам как первый smoke test.

8. СОВМЕСТИМОСТЬ И ПРЕЖНИЙ ПАТЧ MAJOR LEADS
В присланном ZIP прошлый патч Program Proposals лежит внутри files/,
но основной src/App.tsx не содержит его маршрутов. Наличие папки files/
само по себе НЕ подключает обновление к сайту. Этот патч решает только
картинки в письмах и не применяет прошлое обновление Major Leads.
Содержимое старой files/ не менялось и сюда не включено.
Если позже будете объединять оба патча, сохраните оба изменения в
src/lib/types.ts, включая новую email_images у Announcement. Не заменяйте
наугад свежие файлы более старой версией.
